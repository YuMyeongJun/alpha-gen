# Operating Stages

## 단계 정의

`alpha-gen`은 `config.OPERATING_STAGE`를 기준으로 승격합니다.

- `mock`: 시뮬레이션 전용
- `paper`: 실제 데이터 기반 페이퍼 주문
- `shadow`: 주문 의도와 감사 이벤트만 기록, 브로커 제출 없음
- `live_limited`: 실거래 허용, 엄격한 주문 수/손실 한도 적용
- `live_full`: 실거래 전체 자동화

## 단계별 검증 기준

### 1. mock

- 전략 시그널과 포지션 사이징이 의도대로 생성되는지 확인
- 주문 상태 전이와 감사 이벤트가 누락되지 않는지 확인
- 운영 콘솔에 경고/긴급정지 상태가 표시되는지 확인

### 2. paper

- 실제 시세와 뉴스 수집이 정상 동작하는지 확인
- 자동 워커가 `filled/rejected` 상태를 일관되게 기록하는지 확인
- 손절, 드로우다운, 긴급정지가 자동 주문을 차단하는지 확인

### 3. shadow

- 실거래와 동일한 안전정책을 통과해야만 주문 의도가 생성되는지 확인
- 브로커 제출 없이 `reconciled` 상태와 감사 로그가 남는지 확인
- 운영 콘솔에서 shadow 단계가 명확히 보이는지 확인

### 4. live_limited

- `ALLOW_LIVE_TRADING=true` 와 브로커 자격증명이 모두 준비되었는지 확인
- 일일 주문 수, 연속 손실, 일손실 한도가 실제로 차단되는지 확인
- 긴급정지 후 신규 실거래 주문이 모두 거절되는지 확인

### 5. live_full

- broker sync, 주문 전이, 포지션 정합성 점검이 안정적으로 반복되는지 확인
- 운영 콘솔만 보고도 현재 단계, 차단 사유, 최근 이벤트를 추적할 수 있어야 함
- 배포 전 smoke test와 운영 체크리스트를 통과해야 함

## 승격 규칙

1. 한 단계 아래 환경에서 회귀 테스트와 수동 검증을 먼저 끝냅니다.
2. 긴급정지와 감사 이벤트 UI가 준비되지 않았다면 상위 단계로 올리지 않습니다.
3. `live_limited` 이상에서는 안전정책을 우회하는 임시 코드를 넣지 않습니다.
